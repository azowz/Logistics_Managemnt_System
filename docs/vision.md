# رؤية المنتج — مسار (Mesaar)

> **المصدر:** [`archive/01-project-vision.md`](./archive/01-project-vision.md) (الوثيقة المرجعية الأصلية بالإنجليزية). هذه الصفحة خلاصة عربية لها، والتصميم التقني يبقى مرجعه وثائق المعمارية وسجلات القرارات (ADR).

`Mesaar` (مسار) منصة SaaS متعددة المستأجرين (multi-tenant) لإدارة **عمليات النقل البري الثقيل والمتخصص** في المملكة العربية السعودية ودول الخليج. تجمع المنصة بين نواة تشغيلية (دورة حياة الشحنة، والإسناد (dispatch)، والتتبع، وبرج التحكم (control tower)) وبين **تخصص في المعدات الثقيلة**: تصاريح الحمولات الزائدة الأبعاد أو الوزن (oversize/overweight)، والمرافقة (escort)، والامتثال لأوزان المحاور والمسارات، وتأجير المعدات، وشهادات المشغّلين. هذه جوانب لا تغطيها منصات الشحن العامة.

## 1. المهمة

نقل البضائع الثقيلة وعالية القيمة والحرجة زمنيًا عبر المملكة، بمستوى التخطيط والامتثال التنظيمي والرؤية اللحظية الذي تتطلبه المشاريع الكبرى، على منصة واحدة متعددة المستأجرين وقابلة للتدقيق.

## 2. المشكلة

تعاني عمليات النقل الثقيل من احتكاك تشغيلي يجعلها بطيئة ومكلفة وعالية المخاطر:

- متابعة التصاريح يدويًا.
- إسناد الرحلات عبر جداول البيانات.
- غياب أوقات وصول متوقعة (ETA) موثوقة.
- نزاعات حول إثبات التسليم.
- تسويات مالية غير شفافة.

## 3. الرؤية والآفاق الزمنية

أن تكون مسار **نظام السجل (system of record) وطبقة الذكاء** للنقل الثقيل ولوجستيات المشاريع في الخليج، أي برج التحكم الذي تُدار منه حركة المشاريع الكبرى.

| الأفق | المحتوى |
|---|---|
| **H1** | نواة تشغيلية متعددة المستأجرين بجودة الإنتاج: الشحنات، والأسطول والسائقون، وسعة المستودعات، وتتبع إلحاقي فقط (append-only)، والإسناد، وتطبيق سائق عربي أولًا. |
| **H2** | الطبقات التجارية وطبقات الامتثال: الطلبات، والعقود واتفاقيات مستوى الخدمة (SLA) والتسعير، والفوترة والتسوية، ونطاق المعدات الثقيلة (المعدات والأصول، والامتثال والتصاريح، والتأمين والمطالبات). |
| **H3** | طبقة الذكاء: تنبؤ ETA وSLA، والإسناد وتحسين المسارات بالذكاء الاصطناعي، والتنبؤ بتأخر التصاريح وتوفر المعدات والطلب، مبنية على سجل الأحداث غير القابل للتعديل، مع إبقاء الإنسان في الحلقة (human-in-the-loop) للقرارات الحرجة أمنيًا وتنظيميًا. |

## 4. المستخدمون المستهدفون والأدوار

**العملاء الأساسيون:** مشغّلو القطاع الصناعي والمشاريع الكبرى وأذرعهم اللوجستية، في قطاعات الطاقة والبتروكيماويات، ومشاريع البناء والمشاريع العملاقة، والتعدين والصناعات الثقيلة.

**العملاء الثانويون:** ناقلو الحمولات الثقيلة المتخصصون، وشركات الرافعات وتأجير المعدات، ومزودو الخدمات اللوجستية (3PL) الذين يخدمون الفئات السابقة.

**أدوار المستخدمين (RBAC):** تطابق القيم الأربع في `UserRole`:

| الدور | القيمة في الكود | الاستخدام |
|---|---|---|
| مدير النظام (للمستأجر أو المنصة) | `admin` | إدارة المستأجر والمستخدمين والإعدادات |
| مدير العمليات / الإسناد | `manager` | التشغيل اليومي والإسناد وبرج التحكم |
| السائق / المشغّل | `driver` | تطبيق الجوال العربي (RTL) |
| العميل / الشاحن | `client` | بوابة العميل |

أدوار مستقبلية لم تُنفذ بعد: مسؤول الفوترة، ومسؤول الامتثال، ومشغّل المستودع، وصيانة الأسطول.

## 5. الأهداف التجارية

| # | الهدف | المعنى |
|---|---|---|
| O1 | الموثوقية التشغيلية | دورة حياة محروسة للشحنة، وقيود الحصرية والسعة مفروضة في الكود، ولا انتقالات حالة غير مشروعة، وتدقيق بلا فقد. |
| O2 | الامتثال التنظيمي بالتصميم | لا تُسند أي حركة زائدة الأبعاد أو الوزن دون تصريح ساري ومسار مُجاز ومرافقة ومشغّل معتمد، وتُفرض هذه الشروط بوابات إسناد صارمة (HARD dispatch gates). |
| O3 | الرؤية اللحظية وبرج التحكم | موقع حي، وETA تنبؤي، وإبراز مخاطر SLA، وإدارة الاستثناءات لكل حركة وأصل نشط. |
| O4 | النزاهة التجارية | تسعير وSLA قائمان على العقود، وتسوية آلية، ومدفوعات للسائقين والناقلين، ومطالبات وغرامات، مع مطابقة الحركة المالية للعمل المُسلَّم. |
| O5 | استغلال الأصول والأسطول | رفع نسبة استغلال المعدات الثقيلة والمركبات، فهي رافعة التكلفة الأساسية. |
| O6 | الثقة والعزل بين المستأجرين | عزل صارم لكل مستأجر عبر أمان مستوى الصف (RLS)، وإقامة البيانات، وعدم قابلية السجلات للتعديل، ومحو تشفيري (crypto-shred). |
| O7 | ذكاء القرار | نماذج تنبؤ وتحسين تتفوق قياسيًا على التخطيط اليدوي، مع حوكمة قابلة لإعادة الإنتاج ومحصورة بالمستأجر. |

## 6. مستهدفات الأعمال (أولية)

> مستهدفات توجيهية، وليست نتائج أداء مقاسة أو شهادة جاهزية. يعتمد كل مستأجر أهداف مستوى
> الخدمة الخاصة به؛ المصدر التاريخي في [الرؤية الأصلية](archive/01-project-vision.md).

| الفئة | المؤشر | المستهدف |
|---|---|---|
| العمليات | الالتزام بالتسليم في الموعد / SLA | ≥ 95% من الحركات ضمن نافذة SLA |
| العمليات | انتقالات حالة غير مشروعة في الإنتاج | **0** |
| الامتثال | حركات أُسندت دون تصريح أو مرافقة أو شهادة سارية | **0** (بوابة صارمة) |
| الرؤية | الحركات النشطة ذات ETA حي في برج التحكم | ≥ 99% |
| الرؤية | متوسط زمن الإقرار بالاستثناء | < 15 دقيقة |
| التجاري | أتمتة التسوية (من التسليم إلى الفوترة) | ≥ 90% دون تدخل يدوي |
| التجاري | زمن دورة المطالبة (من البلاغ الأول FNOL إلى الإغلاق) | انخفاض 40% |
| الأصول | الاستغلال المنتج للمعدات والمركبات | ≥ 75% |
| المنصة | حوادث تسرب بيانات بين المستأجرين | **0** |
| المنصة | زمن قراءة p95 لإسقاطات برج التحكم | < 300 ms |
| المنصة | حداثة خط الأحداث (تأخر الـ outbox) | < 1 s عند p95 |

## 7. النطاق

- **ضمن النطاق المستهدف (H1/H2):** SaaS متعدد المستأجرين؛ نقل بري ثقيل وزائد الأبعاد والشحن العام؛
  تأجير المعدات؛ الامتثال التنظيمي؛ عمليات عربية RTL؛ بنية أحداث قابلة للتدقيق؛ جاهزية
  للذكاء الاصطناعي. التنفيذ الحالي CQRS-lite مع Outbox، وليس Full Event Sourcing؛
  الرؤية لا تعني تنفيذ التأجير أو كل متطلبات الامتثال.
- **خارج النطاق حاليًا:** سوق ناقلين فوري عام (H3)، والتخليص الجمركي والشحن العابر للحدود، والنقل متعدد الوسائط (بحري/جوي/سككي).

## 8. ما هو منفذ اليوم

- **الخلفية (backend):** تنفذ النطاقات الموثقة في [`domains.md`](./domains.md) (FastAPI ضمن `app/`).
- **لوحات الويب** لأدوار `admin` والعمليات والإسناد (`manager`) والعميل (`client`): **غير موجودة بعد**؛ مواصفاتها في [`../ui/screen-map.md`](../ui/screen-map.md).
- **تطبيق السائق** (`mobile/`): ثلاث شاشات (تسجيل الدخول، ولوحة السائق، وعرض الشحنة)، ويعمل افتراضيًا على **بيانات وهمية (mock)** ما لم يُضبط `EXPO_PUBLIC_USE_MOCK=false`. راجع [`../mesaar-frontend/README.md`](../mesaar-frontend/README.md).
